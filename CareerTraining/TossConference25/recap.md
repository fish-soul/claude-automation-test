# 사용자 경험을 어떻게 수치화할 수 있을까? — 업무 도입 프로세스 정리

> 출처: Toss Conference 2025 | 발표자: 정명화 (토스 UX 리서치팀 리더)

---

## 핵심 요약

토스 UX 리서치팀 리더 정명화님이 **"사용자 내비게이션 경험을 수치화"**한 여정을 공유한 발표입니다. 서비스가 200개 이상으로 늘어나면서 기존 UT(사용성 테스트)만으로는 커버할 수 없는 규모 문제를 해결하기 위해 자체 툴을 개발한 사례입니다.

---

## 업무 도입 가능한 프로세스

### 1. Discovery vs Navigation 분리 진단
**언제 적용:** 서비스/기능이 많아졌을 때, "찾기 어렵다"는 피드백이 올 때

> 발견(Discovery)의 문제인가 vs 탐색(Navigation)의 문제인가를 먼저 구분한다.

- **Discovery 문제**: 이 기능이 있는지 아예 모름 → 마케팅, 노출 전략으로 해결
- **Navigation 문제**: 있다는 건 아는데 못 찾음 → 메뉴 구조, IA, CTA 명칭으로 해결

**실무 적용:** 유저 인터뷰/CS 데이터를 이 두 가지 기준으로 분류해 개선 방향을 다르게 설정

---

### 2. 진입점 사전 검증 (프로토타입 기반, EVR 방식)

**언제 적용:** 개발 전, 신규 기능/메뉴 명칭이나 위치를 결정할 때

> 실제 개발 전에 프로토타입 + 설문으로 사용자가 원하는 기능을 찾을 수 있는지 검증

**운영 방법:**
1. 시나리오 시츄에이션 작성 ("병원비 실비 청구하고 싶을 때, 어디를 누르시겠어요?")
2. 프로토타입 화면 또는 스크린샷에 클릭 영역 설정
3. 소수 사용자(4~5명)에게 배포 → 히트맵으로 클릭 분포 확인
4. 정답 진입점 도달률(%) 산출

**한계:** 사전에 설정한 플로우 안에서만 탐색 가능 → 완전한 자유 탐색 반영 어려움

---

### 3. 실사용 기반 내비게이션 스코어링 (TNS 방식)

**언제 적용:** 출시된 서비스의 내비게이션 품질을 측정하거나 전후 비교할 때

> 실제 앱/서비스 안에서 자유롭게 탐색하면서 정답 진입점 도달률을 측정, 0~100 점수화

**운영 방법:**
1. 측정할 서비스 목록 선정 (MAU 기준 상위 서비스 우선)
2. 각 서비스별 **시나리오 질문 + 정답 로그(경로)** 설정
3. 실사용자에게 푸시 메시지로 테스트 요청 ("토스 화면 개선을 위해 짧은 테스트에 참여해주세요")
4. 정답 도달률을 점수화 → 서비스별 비교 가능한 단일 지표 생성
5. 대시보드 구성:
   - 정답 유저 전이 흐름
   - **오답 유저 전이 흐름** (어디서 헤매는지)
   - 오답에서 가장 많이 진입한 화면(잘못된 연관성 파악)

**토스 실제 결과 예시:**
| 서비스 | 점수 |
|---|---|
| 홈 송금 | 90점 (가장 높음) |
| 전체 평균 | 54점 |
| 신용카드 한도 보기 | 20점 (가장 낮음) |

---

### 4. 인사이트 → 개선안 → 팔로업 사이클

**발표에서 발견된 인사이트 활용 방법:**

```
[문제 발견]
오답 유저 전이 분석에서 "대출 홈까지는 들어오는데 최종 진입점을 못 찾음"

[원인 파악]
CTA 명칭 "내 대출 한도"가 "신용대출"과 연관성이 낮음

[개선안 제안]
A: 신용대출 비교
B: 신용대출 한도 비교
C: 새로운 대출 비교

[검증]
A/B 테스트로 전환율 측정 → 최종 반영
```

**실무 적용 포인트:**
- 정성 인사이트(UT, 인터뷰)와 정량 스코어를 함께 제시하면 팀 공감대 형성이 훨씬 빠름
- 수치는 "설명 없이도 같은 기준으로 볼 수 있는 언어" — 개발/기획팀과 소통 비용 감소
- 개선 제안 후 팔로업(실제 반영 여부 추적)까지 리서처의 책임 범위로 넓히기

---

### 5. 리서치 규모 문제 해결 원칙

기존 UT 방식의 한계:
- 200개 서비스 × 4명 × 30분 = **약 400시간(50일)** 소요

해결 방향:
- 전수 UT 대신 **스코어 기반 모니터링**으로 전환 → 우선순위 낮은 서비스는 스코어만 추적
- MAU 기준으로 서비스 중요도 분류 → 리소스 집중
- 대규모 사용자 대상 **비동기 설문형 테스트** 활용 (연구자 1:1이 아닌 자동화 배포)

## 정리: 단계별 도입 제안

| 단계 | 액션 | 난이도 |
|---|---|---|
| 즉시 | Discovery/Navigation 기준으로 기존 피드백 재분류 | 낮음 |
| 단기 | 신규 기능 출시 전 프로토타입 + 진입점 클릭 테스트 도입 | 중간 |
| 중기 | 주요 서비스별 내비게이션 스코어 정기 측정 체계 구축 | 높음 |
| 장기 | 스코어 기반 개선 → A/B 테스트 → 반영까지 전체 사이클 표준화 | 높음 |
