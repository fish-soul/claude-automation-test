# Claude Automation Test 통합 지침서

이 저장소는 디자인 시스템 및 UX 라이팅 자동화를 위한 모노레포입니다. 클로드, 너는 모든 작업 시 각 하위 폴더에 정의된 독립적인 `CLAUDE.md` 지침을 최우선으로 존중하며 아래 구조에 따라 작업해.

## 📂 폴더별 전문 지침 참조
1. **`/native-ux-writing/`**
   - 역할: 서비스 톤앤매너 및 라이팅 가이드라인의 원천.
   - **규칙:** 모든 문구 교정 및 생성 시, 이 폴더 내의 `CLAUDE.md`에 정의된 라이팅 원칙(해요체/합쇼체 활용법 등)을 반드시 참조하여 적용할 것.

2. **`/design-system-automation/`**
   - **`/baseUI-test/`**: Base UI 기반 컴포넌트 생성 시 해당 폴더의 지침 참조.
   - **`/shadcn-test/`**: shadcn/ui 기반 컴포넌트 생성 시 해당 폴더의 지침 참조.

## 🤖 통합 자동화 워크플로우 (Cross-Referencing)

### 1. 라이팅 우선 원칙
- UI 코드를 짜기 전, 항상 `/native-ux-writing/CLAUDE.md`의 기준에 따라 화면 속 문구를 먼저 검토하고 교정한다.
- 특히 **'해요체'와 '합쇼체'의 엄격한 구분**은 해당 폴더의 가이드라인을 100% 준수한다.

### 2. 디자인 시스템 선택 및 적용
- 사용자의 별도 요청이 없다면 `shadcn-test`를 기본으로 사용한다.
- **중요:** 각 디자인 시스템의 구체적인 구현 방식, 코드 스타일, 라이브러리 활용법은 해당 폴더 내의 `CLAUDE.md` 지침을 100% 신뢰하고 따른다.

### 3. 작업 실행 순서 (Standard Operating Procedure)

클로드, 너는 모든 요청에 대해 아래 4단계 프로세스를 엄격히 준수하며 사고하고 행동한다.

1. **지침 탐색 (Context Retrieval):** - 요청받은 작업의 성격(라이팅, 특정 디자인 시스템)에 따라 해당 하위 폴더의 `CLAUDE.md`를 즉시 찾아 읽는다. 
   - 예: "shadcn으로 해줘" -> `/design-system-automation/shadcn-test/CLAUDE.md` 우선 로드.

2. **라이팅 필터링 (UX Writing First):** - UI를 설계하기 전, `/native-ux-writing/` 폴더의 지침과 그 안의 `CLAUDE.md`를 바탕으로 화면 내 모든 텍스트를 먼저 교정한다.
   - 교정 시 '해요체'와 '합쇼체' 적용 기준을 명확히 구분하여 사용자에게 먼저 제안한다.

3. **시스템 최적화 (System-Specific Implementation):** - 교정된 문구를 반영하여, 선택된 디자인 시스템 폴더의 `CLAUDE.md`가 규정한 코드 스타일, 기술 스택, 디자인 토큰에 맞춰 결과물을 생성한다.

4. **검증 (Final Verification):** - 결과물이 최상위 지침과 각 하위 지침의 충돌 없이 작성되었는지 최종 확인한 후 사용자에게 출력한다.
