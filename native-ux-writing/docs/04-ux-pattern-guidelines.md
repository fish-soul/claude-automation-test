# UX Pattern Writing Guidelines

AI는 새로운 텍스트를 제안할 때, 해당 텍스트가 어떤 UI 컴포넌트에 들어가는지 파악하고 아래의 공식과 제약을 철저히 따릅니다.

## 1. 버튼 (Buttons)
- **공식:** [목적어(옵션)] + [동사 명사형/기형]
- **제약:** 띄어쓰기 포함 최대 10자를 넘지 않습니다. '확인/취소' 같은 모호한 쌍 대신, 누르면 어떤 일이 일어나는지 명확히 씁니다.
  - (X) "예 / 아니오" (팝업: 토큰을 전송할까요?)
  - (O) "전송하기 / 취소"
  - (O) "주소 복사", "내역 보기", "다시 시도"

## 2. 얼럿 팝업 (Alert Dialogs)
사용자의 흐름을 강제로 끊는 요소이므로 가장 직관적이어야 합니다.
- **Title (제목):** 일어난 상황의 '결과'나 사용자가 해야 할 '핵심 행동'을 요약합니다. 마침표 생략. (예: "잔액이 부족해요")
- **Body (본문):** 그 상황이 발생한 '이유'와 '해결책'을 씁니다. 2줄을 넘지 않도록 작성하며 마침표를 찍습니다. (예: "가스비로 사용할 KLAY가 부족해요. 지갑에 KLAY를 채운 후 다시 시도해 주세요.")
- **Action (버튼):** 본문을 읽지 않고 제목과 버튼만 봐도 행동을 결정할 수 있게 연결합니다. (예: "충전하기", "닫기")

## 3. 토스트 및 스낵바 (Toasts & Snackbars)
화면 하단에서 3초간 떴다가 사라지는 메시지입니다.
- **공식:** [대상] + [완료된 행동(과거형)]. 마침표 생략.
- **제약:** 순식간에 사라지므로 최대 1줄(약 20자 이내)로 작성하며, 실패/에러 상황에는 토스트 대신 얼럿 팝업을 씁니다.
  - (O) "지갑 주소를 복사했어요"
  - (O) "관심 목록에 추가했어요"

## 4. 빈 화면 (Empty States)
데이터가 없을 때 노출되는 화면입니다.
- **Title:** 무엇이 비어있는지 명시 (예: "아직 전송 내역이 없어요")
- **Body:** 어떤 활동을 하면 이곳이 채워지는지 안내 (예: "토큰을 전송하면 이곳에 내역이 기록돼요.")
- **Action:** 데이터를 채울 수 있는 시작점으로 이동하는 버튼 제공 (예: "첫 전송하기")

## 5. 입력 필드 힌트 (Placeholders)
사용자가 무엇을 입력해야 하는지 예시를 직접적으로 보여줍니다.
  - (X) "지갑 주소를 입력해 주세요."
  - (O) "0x로 시작하는 지갑 주소 입력"
